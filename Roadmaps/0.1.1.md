## 1. TapTap 首次上架准备

- 状态：`进行中`
- 目标版本：`0.1.1`
- 完成日期：`—`
- 提交：`—`

### 设计目标

- 收尾 `0.1.0` 已实现内容的发布材料、包体和平台验收，不引入新玩法。
- 交付可直接提交 TapTap 的 Android Release、文案、图标、截图、视频、宣传图和隐私政策。
- 所有商店素材与实际游戏画面、应用名称和包体能力一致。
- 日常开发只构建 Mac Debug，正式打包时才构建 Android Release APK。
- 外部资质、防沉迷材料和签名材料备份状态明确，不把平台硬性缺口误记为完成。

### 实现内容

- 将工程版本和 Android Version Name 同步为 `0.1.1`，VersionCode 递增为 `2`。
- 重录三关版本的 3 张 `1920x1080` 截图和连续实机视频，覆盖生命 HUD、检查点恢复与通关庆祝。
- 重新设计宣传图，统一屋顶透视和人物比例，不使用拉伸或与实机不符的画面。
- 在 Android ARM64 真机对照最终素材、手势引导、安全区域、音频、发热和帧率。
- 正式提交前复核 TapTap 名称占用、页面字段、APK 包信息和签名。
- 由发布主体补齐 TapTap 要求的资质、ISBN 和未成年人防沉迷材料。
- 对 release keystore 与 Keychain 凭据完成安全的离机备份。

### 验收标准

- TapTap 必填文案、图标、截图、视频、宣传图、隐私政策和 APK 均可直接提交。
- Android Version Name 为 `0.1.1`、VersionCode 为 `2`，应用名、包名、架构、SDK 级别和 v2 签名复核通过。
- 最终 Android Release 在至少一台 ARM64 真机完成完整流程烟测。
- 外部资质和防沉迷材料满足平台要求，或由用户明确记录处理决定。
- 发布提交或 tag、APK SHA-256、测试结果和人工验收记录完整。

### 验收结果

- 已验证：Android Release 使用项目独立证书，凭据缺失时不会回退到 Debug 签名。
- 已验证：Android 应用显示名为 `天台疾跑`，包名为 `com.hackcpp.rooftoprunner`。
- 已验证：构建图标与 TapTap 上传图标使用同一画稿。
- 已验证：三关、生命 HUD、检查点恢复、终点线和通关庆祝通过人工验收。
- 已验证：隐私政策按 TapTap 模板扩充并通过 GitHub Pages 发布。
- 尚未验收：版本号同步、最终商店素材、Android 真机对照、资质、防沉迷材料和签名材料离机备份。

## 2. 新手手势引导真机验收

- 状态：`进行中`
- 目标版本：`0.1.1`
- 完成日期：`—`
- 提交：`75d7927`

### 设计目标

- 初次用户能够从连续动画直接理解左、右、上、下四向滑动操作。
- 手势提示不遮挡标题、按钮、玩家、前方障碍或系统安全区域。
- 动画只在移动端开始页显示，不影响桌面流程、暂停和结算界面。

### 实现内容

- 使用程序化手指轮廓、滑动轨迹和方向箭头循环演示四向手势。
- 移除含义模糊的静态黄色触点。
- 使用不受暂停影响的时间推进，并保持无外部图片资源。
- 在 Android 真机检查实际轮廓、循环节奏和横屏安全区域。

### 验收标准

- 四个方向在一个短循环内全部展示，移动过程和方向清晰。
- 轨迹、箭头、标题、成绩和按钮之间无重叠。
- PlayMode、Mac Debug、Android Release 与 Android ARM64 真机检查均通过。

### 验收结果

- 已验证：PlayMode 覆盖显示状态、四方向循环、布局边界和静态触点移除。
- 已验证：Mac 构建和 Android Release 自动化回归通过。
- 尚未验收：Android 真机上的手指轮廓、四方向节奏和安全区域实际可读性。

- 状态：`暂缓`
- 目标版本：`0.1.1`
- 完成日期：`—`
- 提交：`—`

### 设计目标

- `com.hackcpp.rooftoprunner`、Version Name、VersionCode、ARM64、最低 API 24 和目标 API 35 符合 `0.1.1` 发布要求。
- PlayMode、Mac Debug、Android Release、APK v2 签名和真机回归通过。

### 验收结果
