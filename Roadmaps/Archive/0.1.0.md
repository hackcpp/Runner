## 1. 核心玩法与工程基线

- 状态：`已完成`
- 目标版本：`0.1.0`
- 完成日期：`2026-07-25`
- 提交：`039c2d5`

### 设计目标

- 建立稳定、清晰、可验证的三车道跑酷核心闭环。
- 保持自定义坐标运动和旧 Input API，不引入 Rigidbody、CharacterController 或新输入系统。
- 让障碍生成、固定种子和完整生存路径能够由纯 C# 模拟器重复验证。
- 将游戏状态、HUD、相机、世界池和跑局模拟拆分到明确的组件边界。

### 实现内容

- 完成三车道换道、跳跃、滑铲、输入缓冲、动作中换道和自定义逻辑碰撞体。
- 完成 `Blocker`、`Hurdle`、`Overhead` 三类障碍、12 个模式、固定教学序列和三级难度。
- 完成距离分、动作奖励、连击倍率、最佳成绩、粒子、相机反馈和独立音效。
- 完成开始、暂停、继续、失败、重开和响应式 Canvas HUD。
- 拆分相机、HUD、世界对象池和固定种子跑局模拟，移除视觉几何体的 PhysX Collider。
- 建立 macOS Release、Universal Binary、ad-hoc 签名和 TapTap 打包入口。

### 验收标准

- 三类障碍规则、输入缓冲、动作限制和存档兼容性不得回退。
- 每个模式及模式边界必须存在可验证的生存路径，固定种子必须复现完整障碍序列。
- 动作奖励只能结算一次，绕开动作障碍不得获得动作奖励。
- 10 分钟等效跑局中活动对象和对象池容量保持有界。
- HUD 在 `1280x720` 与 `1440x900` 下无文字重叠。
- Release 为 `x86_64 + arm64` Universal Binary，签名和启动烟测通过。

### 验收结果

- PlayMode `17/17` 通过。
- 5000 个固定种子、每局 1200 米完整生存路径验证通过。
- 10 分钟对象池模拟通过，视觉几何体无启用的 PhysX Collider。
- macOS Release、Universal Binary、签名、双尺寸界面和启动烟测通过。

## 6. 背景音乐与动态编排

- 状态：`已完成`
- 目标版本：`0.1.0`
- 完成日期：`2026-07-27`
- 提交：`2b865fe`

### 设计目标

- 降低短循环重复感，让菜单、常规跑动和高强度跑动具有可辨识的动态层次。
- 给跳跃、滑铲、得分和碰撞等动作音效保留清晰空间。
- 保持音频对象复用，不在重开、暂停或恢复时重新创建 `AudioClip` 或 `AudioSource`。
- 使用相位连续或等响交叉淡化消除循环点音量下陷和爆音。

### 实现内容

- 将单轨 32 拍循环升级为同步的氛围、节奏和高强度三层 64 拍循环，每层约 `30.48s`。
- 三层在同一 DSP 时间点开始播放，只通过权重改变强度。
- 菜单、低强度跑动、`400m+` 高强度跑动和结算使用不同层级权重，并在 `0.72s` 内交叉淡化。
- 跳跃、滑铲、落地、得分和碰撞触发约 `-3dB` 闪避，攻击 `0.04s`、恢复 `0.32s`。
- 合成后移除直流偏移并限制峰值，循环边界不再使用整体首尾淡出。
- 为每层保留样本数、时长、峰值、直流偏移、接缝差和有限样本指标，供 PlayMode 自动验证。

### 验收标准

- 三种运行状态听感可区分，状态变化在 `0.4-1.2s` 内平滑完成且无可闻爆音。
- 主循环不少于约 `30s`；样本绝对峰值不高于 `0.92`、直流偏移绝对值不高于 `0.001`、循环首尾样本差不高于 `0.02`，输出不削波。
- 音乐不会掩盖动作音效，连续试听 5 分钟没有明显频率刺耳、节奏疲劳或循环断层。
- 重开、暂停、恢复和 10 分钟等效运行不会新增音源或片段。
- PlayMode 覆盖片段结构、样本有效性、状态切换和对象复用。

### 验收结果

- `git diff --check` 和 C# 编译通过。
- 完整 PlayMode `19/19` 通过，新增分层结构、样本质量、交叉淡化、闪避和对象复用测试。
- 5000 个固定种子跑局和 10 分钟对象池模拟继续通过。
- macOS Release 为 `x86_64 + arm64` Universal Binary，版本保持 `0.1.0`，严格签名通过。
- 独立 Player 的开始、跳跃、滑铲、碰撞、重开、暂停、恢复和退出正常，日志无异常。
- 使用耳机与扬声器各连续试听至少 5 分钟，动作音效清晰，无明显刺耳、疲劳或循环断层。
