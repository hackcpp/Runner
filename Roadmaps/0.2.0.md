# Rooftop Runner 0.2.0 路线图

- 规划版本：`0.2.0`
- 版本状态：`进行中`
- 版本定位：针对外部体验反馈进行产品级重构，强化中文移动端体验、楼顶辨识度、角色表现和关卡独特性
- 前置版本：[Archive/0.1.1.md](Archive/0.1.1.md)，已完成 TapTap 测试上架并归档
- 目标平台：Android 优先，Mac Debug 用于日常开发验证
- 规划日期：`2026-08-03`

## 1. 产品方向与核心差异化

- 状态：`待处理`
- 目标版本：`0.2.0`
- 完成日期：`—`
- 提交：`—`

### 设计目标

- 正面处理“未汉化、玩法大众、角色像素块、环境不像楼顶、关卡只改变时间与速度、建议竖屏”的外部体验反馈。
- 将核心体验从普通三车道避障调整为“在真实可辨识的楼顶空间中读取安全路线与高风险高收益路线”。
- 保留三车道、跳跃、滑铲、生命、检查点和确定性验证基础，但不把速度、距离或色调变化当作关卡创意。

### 实现内容

- 在实现前完成竖屏构图、楼顶路线和关卡独占机制的低成本原型。
- 明确安全路线、高分路线、楼间跨越和关卡机制之间的规则边界。
- 定义 `0.2.0` 不包含的范围，避免同时引入自由移动、攀爬、成长、联网或其他大型系统。

### 验收标准

- 一句话可以清楚说明本作区别于普通三车道跑酷的核心决策。
- 原型能够同时展示楼顶空间、路线选择和至少一种非传统静态障碍机制。
- 核心方向通过人工评审后，才进入角色、环境和完整关卡制作。
- 新规则能够继续由固定种子模拟器验证，不依赖 Rigidbody 或不可复现的随机物理结果。

### 验收结果

- 尚未执行：产品原型、差异化评审和范围冻结。

## 3. Android 竖屏体验重构

- 状态：`待处理`
- 目标版本：`0.2.0`
- 完成日期：`—`
- 提交：`—`

### 设计目标

- 使用竖屏强化前方路线纵深、单手触控和移动端产品辨识度。
- 竖屏不是简单裁切横屏画面，必须重新平衡相机、视距、HUD、手势区域和障碍预警。
- Mac Debug 继续支持本地测试竖屏布局，Android Release 固定为竖屏方向。

### 实现内容

- 先制作 `1080x1920` 竖屏可玩原型，对比现有横屏的路线可读性、角色占屏和反应时间。
- 重设相机位置、FOV、前方可见距离、速度反馈和碰撞震动幅度。
- 重排 HUD、安全区域、暂停入口、面板按钮和四向手势引导。
- 更新 Android 方向设置、Mac Debug 测试窗口和响应式布局测试。

### 验收标准

- 原型人工评审确认竖屏优于横屏后，才固定 Android 竖屏配置；若不成立，记录证据并保留横屏。
- 玩家在最高速度下仍具有不低于既定规则的动作响应时间，障碍不因窄视野突然出现。
- 常见 `9:16`、`9:19.5`、`9:20` 设备及安全区域下 HUD、手势和面板无重叠。
- Android 真机完成开始、手势、暂停、受击、继续、通关和退出全流程。

### 验收结果

- 尚未执行：竖屏原型、横竖屏对比、方向切换和真机验收。

## 4. 角色模型与动作反馈升级

- 状态：`待处理`
- 目标版本：`0.2.0`
- 完成日期：`—`
- 提交：`—`

### 设计目标

- 消除基础 Cube 拼接形成的“像素块人物”观感，建立清晰、统一且适合竖屏远近尺度的角色轮廓。
- 动作反馈不仅依靠粒子和相机，角色本体要表现起跳准备、腾空、落地缓冲、滑铲惯性、换道重心和碰撞失衡。
- 模型、材质与动画资源保持可编辑、来源清晰，并适合 Android 性能预算。

### 实现内容

- 使用正式的风格化低多边形角色网格和骨骼层级替换运行时 Cube 拼装外形。
- 制作或接入跑步、跳跃、落地、滑铲、换道、碰撞和庆祝动画，并处理动作间过渡。
- 保持逻辑碰撞体与视觉模型解耦，不改变既有自定义坐标运动规则。
- 建立角色三角面、骨骼、材质、纹理和 Animator 开销预算。

### 验收标准

- 静止截图中角色不再呈现方块拼装感，正背面和动作方向均易辨识。
- 跑、跳、落地、滑铲、换道、碰撞和庆祝均有可读的预备、主动作与收势反馈。
- 视觉动画不改变逻辑碰撞高度、动作时长或固定种子生存结果。
- Android 真机目标帧率和内存无明显回退，资源授权与可编辑源文件完整。

### 验收结果

- 已确认：当前角色由 `PrimitiveType.Cube` 部件拼装，动作表现受基础轮廓限制。
- 尚未执行：模型选型、骨骼动画、性能预算和真机检查。

## 5. 楼顶环境辨识度升级

- 状态：`待处理`
- 目标版本：`0.2.0`
- 完成日期：`—`
- 提交：`—`

### 设计目标

- 玩家在不看标题的情况下也能立即判断自己正在楼顶奔跑，而不是在一条悬空平面上移动。
- 主路线包含楼体边缘、立面、高低差、楼间关系和可记忆地标，背景建筑不再承担全部楼顶语义。
- 环境变化服务路线判断，不能只增加装饰密度或依赖颜色区分。

### 实现内容

- 将连续屋面拆为可验证的楼顶段，加入逻辑楼间缺口、高低屋面和明确的跨楼连接。
- 强化女儿墙、楼体立面、机房、楼梯间、消防水箱、通风设备、广告牌和施工设施的尺度关系。
- 为每关建立独立的建筑类型、天际线轮廓、地标和路线语言。
- 重复环境对象继续池化，视觉几何体不携带启用的 PhysX Collider。

### 验收标准

- 首个游戏画面和任意关卡截图都能清楚显示楼体、屋面边缘和周围城市高度关系。
- 楼间缺口和高低变化具有明确预警、可学习规则和固定种子生存路径。
- 三关使用不同的建筑结构和地标，不得仅通过天空、雾、灯光或时间变化区分。
- 10 分钟运行及多次关卡重置后对象池容量保持有界，Android 性能符合预算。

### 验收结果

- 已确认：当前虽有女儿墙、HVAC、天窗、水箱和背景建筑，但主路线仍表现为连续平面。
- 尚未执行：楼顶段设计、楼体立面、高低差、地标和性能验证。

## 6. 三关独占机制与风险收益路线

- 状态：`待处理`
- 目标版本：`0.2.0`
- 完成日期：`—`
- 提交：`—`

### 设计目标

- 每关拥有独占且可操作的机制，速度、距离、障碍数量和时间色调不计为关卡差异。
- 玩家在安全路线与高风险高收益路线之间做清晰决策，使玩法重点从被动反应提升为路线规划。
- 新机制逐关教学、组合和升级，但不制造不可读或无解序列。

### 实现内容

- 第 1 关聚焦楼间跨越与基础路线判断，建立安全路线和奖励路线的视觉语言。
- 第 2 关使用施工楼顶、高低路线与确定性移动吊臂，要求结合换道和动作时机。
- 第 3 关使用屋顶追逐、逐段失效路线或无人机干扰，组合前两关能力并形成压迫感。
- 将新机制、奖励轨迹、强制动作间距和关卡边界同步到 `RunnerGameplay` 与 `RunnerRunSimulation`。

### 验收标准

- 每关至少一个其他关卡不存在的核心机制，并能在进入关卡后 `10s` 内被玩家感知。
- 每个风险路线都提供可量化奖励，安全路线始终存在且不会被奖励引导误标为无解路线。
- 固定种子复现完整环境与障碍序列；模式、边界、高低路线和移动机制均存在可验证生存路径。
- 至少覆盖 5000 个固定种子、每关完整距离、最高速度响应时间和多次检查点恢复。

### 验收结果

- 已确认：当前三关主要通过距离、速度、种子、难度层级和环境色调区分，缺少独占机制。
- 尚未执行：关卡机制原型、风险收益规则、模拟器扩展和批量测试。

## 9. Android 签名材料离机备份

- 状态：`待处理`
- 目标版本：`0.2.0`
- 完成日期：`—`

### 设计目标

- 确保 release keystore 和对应密码凭据在当前 Mac 丢失或损坏后仍可恢复，避免永久失去同包名应用的升级能力。
- 备份过程不得把 keystore、密码、Keychain 导出或恢复口令提交到 Git、Distribution 公共材料或普通云盘明文目录。

### 实现内容

- 将 `Distribution/Signing/RooftopRunner-release.keystore` 保存到受控的离机介质或加密备份位置。
- 使用安全方式分别备份 macOS Keychain 服务 `RooftopRunner Android Release` 的 `storepass` 与 `keypass` 恢复信息。
- 记录备份日期、介质或保管位置标识和恢复验证结果，不在仓库记录秘密值。
- 在隔离临时环境验证 keystore、alias 和凭据能够完成签名，再清理临时副本。

### 验收标准

- keystore 与密码恢复信息至少存在一份不依赖当前 Mac 的安全副本。
- 备份副本访问受控且非明文公开，Git 历史和工作区均不包含秘密值。
- 使用备份恢复的材料可以对测试 APK 完成签名，证书 SHA-256 仍为 `3ebc01d8289f5d8caa669ff5c8ad60fa6e5d6e37971fd3802ec153af2fb8a710`。
- 路线图只记录恢复验证结论和非敏感位置标识。

### 验收结果

- 已验证：当前构建机上的 keystore 和 Keychain 凭据能够生成 `0.1.1` v2 正式签名 APK。
- 迁移记录：本条从 `0.1.1` 收尾风险迁入 `0.2.0`，未完成前不得删除当前构建机上的签名材料。
